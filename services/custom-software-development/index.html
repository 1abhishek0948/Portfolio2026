Custom Software Development in Nepal

When spreadsheets stop scaling and generic software doesn't fit how you actually work, custom software fills the gap. I build internal tools, management systems and automations that match your business process — not the other way around.

Kinds of software I build

  • Management systems — inventory, billing, student or member records, appointments: the daily operations of a business in one reliable place
  • Internal tools — dashboards and admin panels that make your data usable instead of buried in files
  • Automation — repetitive work like data entry, report generation, notifications or file handling turned into code
  • Portals and platforms — multi-user applications with roles, permissions and structured workflows (see LAHAN Hub for a large example)

Why custom — and when not

Custom software pays off when your process is genuinely different, when off-the-shelf tools force workarounds, or when you're building something new. It doesn't pay off when a free tool already does the job. I'll tell you which situation you're in before you spend anything — sometimes the honest answer is "use this existing product for now".

How a project runs

We start by mapping how your business actually works today — the paper, the phone calls, the spreadsheets. From that I propose a data model and a phased plan: the smallest useful version first, then extensions. Systems grow with use, so I keep the architecture well-modelled at the database level and document what exists. If you have existing tools, I build integrations instead of replacing everything at once.

You own what I build

Source code, database and deployment belong to you, in your accounts, from day one. I work in the open: you can see progress throughout, not just at the end. After delivery, ongoing support is available but never compulsory.

Where I work

I work with businesses in Lahan and Siraha directly, and with clients across Nepal — Kathmandu, Birgunj, Biratnagar, Pokhara — remotely. Business-process workshops work well over video calls.

Frequently asked questions

Can you digitise how our business currently works on paper?

Yes — that's one of the most common starting points. We document the current process, find which steps genuinely need to stay manual, and build software around the rest.

Can the software work with tools we already use?

Usually, yes, if the other tool offers an export or an API. I've integrated payment, email, AI and data services; where a tool has no integration path, I design an import/export fallback.

Who owns the code and the data?

You do. The repository, database and hosting accounts are created in your name or transferred to you. You're never locked into me to keep your own software running.

What happens after it's delivered?

You get documentation, a walkthrough, and the option of ongoing maintenance. If you later hire another developer, the codebase is structured and documented so they can take over.
